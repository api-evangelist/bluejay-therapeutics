individual post permalinks also still resolve. For this company the API is now a more complete
public record than the web site it belongs to. The content is frozen — nothing has been published
since the acquisition — so treat it as a closed historical archive.

## How to read the archive

Get the whole index in one call — do not page through full bodies unless you need them:

    GET https://bluejaytx.com/wp-json/wp/v2/posts?per_page=100&_fields=id,slug,date,title,link,categories

Then fetch bodies selectively:

    GET https://bluejaytx.com/wp-json/wp/v2/posts/{id}

Filter to press releases (category 14) or publications (category 17):

    GET https://bluejaytx.com/wp-json/wp/v2/posts?categories=14&per_page=100

Isolate the substantive PDFs in the media library:

    GET https://bluejaytx.com/wp-json/wp/v2/media?mime_type=application/pdf&per_page=100

Search across the archive:

    GET https://bluejaytx.com/wp-json/wp/v2/search?search=brelovitug&per_page=100

Notes that will save you time:

- `content.rendered` is HTML, and newer posts are wrapped in Elementor `div[data-elementor-type]`
  scaffolding around the prose. Strip it.
- `guid.rendered` looks like a URL but is a frozen internal identifier pointing at a WP Engine
  staging host. It does not resolve. Use `link`.
- Totals come back in the `X-WP-Total` and `X-WP-TotalPages` response headers.
- `per_page` is capped at 100; exceeding it returns 400, not a clamp.
- Six collections answer 200 with an empty array — comments, portfolio, portfolio_category,
  portfolio_tag, blocks, navigation. Empty is a success, not a retryable failure.
- No rate-limit headers are published. robots.txt asks for a 10-second crawl delay. Self-throttle.

## Not available

Stated so an agent stops looking: no developer portal, no API documentation, no API reference, no
getting-started guide, no SDKs, no CLI, no package-registry presence (npm, PyPI and the rest all
miss), no GitHub organisation, no Postman collection, no sandbox, no pricing, no signup, no support
channel, no status page, no changelog, no webhooks, no events, no AsyncAPI, no GraphQL, no MCP
server, no A2A agent card, no security.txt, no trust center, no compliance program, and — since the
teardown — not even a privacy policy. No `api.`, `developer.`, `docs.`, `portal.`, `status.`,
`trust.` or `security.` subdomain resolves.

The site does register the WordPress Abilities API (`wp-abilities/v1`), the agent-facing capability
registry, but every route under it returns 401 to anonymous callers. There is no agent surface here.

`/wp/v2/users` returns author records anonymously. It is deliberately excluded from the OpenAPI and
from the agent skills as personal data, and no tool is provided for it.
